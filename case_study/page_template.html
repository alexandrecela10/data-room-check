01 · VISION

No investment decision rests on a number nobody checked.

The deck is written to sell. The data room holds the truth, across hundreds of files you don't have time to read. The vision: every claim checked, every file read, and every result one click from its source page.

02 · THE PROBLEM

Three things go wrong today.

1 · Decisions on wrong numbers

The family decides on figures the seller chose to show. You can only check the ones you have time for, so a wrong one can reach the decision.

2 · Decisions without the full picture

A lawsuit, a loan that must be repaid if owners change, a CFO who left. They sit in files you never had time to open.

3 · The same work, done twice

Your associate can't see what you checked or where, so they re-read the files before signing off.

03 · THE SOLUTION

The AI reads. Code checks. You decide.

  1. Every number in the deck is checked. The AI finds the matching figure in the data room. Code confirms the quote is on the cited page, does the arithmetic and sets the status: confirmed, contradicted, conflict or not found.
  2. Every file is read for red flags. 7 checks, every page, no search, so nothing is skipped. Plus anything unusual the list doesn't name.
  3. Every result shows its page. The quote is boxed on the source page. If code can't find it there, the result is labelled unverified, never shown as fact.

06 · LIMITATIONS

What this doesn't prove yet.

  • Fictional data. One company, 13 files. Real data rooms hold hundreds.
  • Tuned on its own test. The instructions were revised 3 times on this data room. A data room they've never seen is the real test.
  • No user tests. Time saved is unobserved.
  • Search index cost unreported. The embeddings service gives no token counts.
07 · SCOPE AND NEXT STEPS

What it won't do, and what comes next.

Non-goals
  • Advice or a price. The decision is yours.
  • Free questions about anything. A search can't prove a fact is absent.
  • Hundreds of files, privacy, logins. Out of scope for the prototype.

Main learnings which search method wins, and the day search said a wrong number was right

The same AI and the same code checks, with four ways to choose what the AI reads. That choice decides the cost, the speed and what can be missed.

Which one wins

  • Small data room (fits in one call): A. It can't miss a page, and the extra cost is cents.
  • Real data room (hundreds of files): D. It reads the fewest passages and keeps sections whole.
  • B alone is the cheapest and the riskiest: when it misses a page, nothing looks wrong.
  • Red flags never use search. Only reading every page proves coverage.

A hypothesis: all four pass on this data room. The scale test is in the next steps.

The day search said a wrong number was right

On the first prompt, RAG confirmed the deck's $38.0M. It read the monthly accounts ($38.0M, with a $1.8M one-off fee) but never the audited accounts ($36.2M). Every quote it gave was real, so the code checks passed.

Checks catch a wrong quote. They can't catch a page that was never read.

The fix: at most 2 passages per file, so 12 look-alike monthly pages can't crowd out the one audited table.

How it was evaluated answer key, pass bar, 3 prompt versions, Langfuse

The bar to ship: every result proven by code (lineage 100%), no missed issue (recall 100%), at least 90% of flags real (precision). The answer key (4 wrong numbers, 6 right ones, 6 red flags) was written before the first run and never changed.

How it's built pipeline, cost and time per method
  1. Read the deck: the AI lists every checkable number. Code checks each quote is on its slide.
  2. Pick what to read: method A, B, C or D chooses passages from the [[n_units]] in the data room.
  3. Find evidence: the AI returns file, page, exact quote and value.
  4. Check it: code confirms the quote is on the page, the number is in the quote, the unit and year match; computes ratios; decides the status.
  5. Hunt red flags: every page of every file against 7 checks; code checks every quote and scans the wording for advice.
